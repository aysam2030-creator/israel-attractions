## 2024-06-21 - React-Leaflet Props Reference Stability
**Learning:** In `react-leaflet`, passing inline objects (like `pathOptions={{ color: "#a78bfa", weight: 4 }}`) to map components or recreating Leaflet objects (like `L.divIcon()`) on every render can cause severe performance issues because it constantly triggers Leaflet layer updates due to changing object references.
**Action:** Always extract static options objects (like `pathOptions`) to constants outside the component, and memoize or cache dynamically generated Leaflet objects (like `L.divIcon` instances).
## 2024-06-21 - Android CI build failure fix for ignored Capacitor plugins
**Learning:** CI builds can fail trying to read `cordova.variables.gradle` if `capacitor-cordova-android-plugins` is not present (e.g. because `npx cap sync android` wasn't run on CI or the directory is gitignored).
**Action:** Always dynamically create a minimal `build.gradle` and `cordova.variables.gradle` inside `android/settings.gradle` for the `capacitor-cordova-android-plugins` directory before it gets referenced by Gradle, ensuring the build succeeds without the need for manual Capacitor syncs on CI.
## 2024-06-21 - Android CI build failure fix for ignored Capacitor plugins
**Learning:** CI builds can fail trying to read `cordova.variables.gradle` if `capacitor-cordova-android-plugins` is not present (e.g. because `npx cap sync android` wasn't run on CI or the directory is gitignored). If `JavaVersion.VERSION_21` is hardcoded in generated files like `android/app/capacitor.build.gradle` and GitHub actions uses a different JDK version (e.g., 17), the build will fail with `invalid source release: 21`.
**Action:** Do NOT modify `sourceCompatibility` or `targetCompatibility` in generated files manually, and do not forcibly commit generated Capacitor plugin directories to bypass CI errors unless explicitly instructed. In Vite + React + Capacitor projects, ensuring the `dist` directory exists by running `npm run build` is required before `npx cap sync android`. If plugins directory issue persists on CI, it's safer to ensure `npx cap sync android` runs in the workflow rather than creating empty stubs. Wait for explicit instructions if unsure.
## 2024-06-21 - Android CI Capacitor Build Compatibility
**Learning:** Capacitor v8 generated files (e.g., `android/app/capacitor.build.gradle` and internal plugin build files) use `JavaVersion.VERSION_21`. If the GitHub CI workflow uses JDK 17 (`actions/setup-java@v4` with `java-version: "17"`), it causes the `invalid source release: 21` error during compilation.
**Action:** When bumping or working with Capacitor v8, verify that the CI workflow (e.g. `.github/workflows/android-build.yml`) uses JDK 21 (`java-version: "21"`) instead of JDK 17.
